# handoff.md — 언제볼래 인수인계

기준 문서: [PRD.md](PRD.md) v1.1 · 갱신일 2026-11-24
이 문서는 이어서 작업할 사람을 위한 것이다. 앞부분은 샘플 모임 하나로 데이터가 어떻게 흐르는지 따라가고, 뒷부분은 지금 상태와 이어서 할 일, 남은 질문을 적는다.
구조와 데이터 모델은 [architecture.md](architecture.md)에 있다.

## 한눈에 보기

```
[로그인] 이름 + 4글자 비밀번호
    ▼
① 가입·로그인          users에 한 줄, 세션 시작
    ▼
② 모임 만들기          rooms에 한 줄 + 모임장 profiles 한 줄 → 링크·암호 복사
    ▼
③ 친구 참여            링크 열기 → (로그인) → 모임 암호 → profiles 한 줄
    ▼
④ 불가능한 날 X        드래그 → 손 뗄 때 바뀐 날만 offDays에 반영 → 다른 탭에 알림
    ▼
⑤ 집계                 tally: 날짜마다 가능한 사람 / 불가능한 사람      ← 규칙
    ▼
⑥ 순위                 ranking: 인원 많은 순, 같은 인원은 같은 순위       ← 규칙
    ▼
⑦ 약속                 모임장이 약속을 만들고(날짜 미정) → 날짜를 골라 확정 → 공지·초대장
                       X는 그대로 남고, 다음 약속을 같은 모임에서 또 잡는다
```

AI는 어디에도 쓰지 않는다.

## 데모: 샘플 모임 따라가기

`scripts/check-tally.mjs`와 같은 샘플을 쓴다. 세 사람 가·나·다, 기간은 11/1 ~ 11/4.

### ① 가입·로그인

「가」가 이름 `가`, 비밀번호 `1234`로 들어온다. 처음 보는 이름이라 가입할지 한 번 묻는다.

```
users['가'] = { name: '가', password: '1234', createdAt: '…' }
eonje:session:v1 = { name: '가', signedInAt: 1761…, lastSeen: 1761… }
```

### ② 모임 만들기

「가」가 모임 이름 `동기 송년회`, 암호 `2580`으로 모임을 만든다. 만든 사람이 모임장이고, 바로 참여한 상태가 된다.

```
rooms['aB3dEf'] = { id: 'aB3dEf', title: '동기 송년회', password: '2580', hostUser: '가', confirmedDate: null, … }
profiles += { id: 'a', roomId: 'aB3dEf', user: '가', name: '가', … }
```

복사되는 글: `[동기 송년회] 불가능한 날을 표시해 줘!\nhttp://…/r/aB3dEf\n암호: 2580`

### ③ 친구 참여

「나」·「다」가 링크를 연다. 로그인 전이면 주소를 기억해 두고 로그인 화면으로 갔다가, 로그인 후 모임으로 돌아온다. 모임 암호를 맞히면 profiles에 한 줄씩 생긴다. 8명이 차면 더 들어올 수 없다.

### ④ 불가능한 날 X

| 사람 | 불가능한 날 |
|---|---|
| 가 | 11/1 |
| 나 | 11/1 |
| 다 | 11/2 |

달력에서 첫 칸을 누를 때 그 칸이 비어 있으면 「표시」, 이미 X면 「지우기」로 정하고, 드래그하는 동안 같은 동작을 칠한다. 손을 떼면 실제로 바뀐 날만 `saveOffDays(roomId, [{ date, off }])`로 보낸다.

```
offDays = [
  { roomId: 'aB3dEf', profileId: 'a', date: '2026-11-01' },
  { roomId: 'aB3dEf', profileId: 'b', date: '2026-11-01' },
  { roomId: 'aB3dEf', profileId: 'c', date: '2026-11-02' },
]
```

저장 뒤 `offdays_changed`를 보내서, 같은 방을 연 다른 탭에 「방금 다님이 날짜를 바꿨어요」가 뜬다.

### ⑤ 집계 (`tally`)

| 날짜 | 가능한 사람 | 불가능한 사람 |
|---|---|---|
| 11/1 | 다 | 가, 나 |
| 11/2 | 가, 나 | 다 |
| 11/3 | 가, 나, 다 | |
| 11/4 | 가, 나, 다 | |

### ⑥ 순위 (`ranking`)

| 순위 | 날짜 | 가능 |
|---|---|---|
| 1 | 11/3 | 3/3명 (모두 참석 가능) |
| 1 | 11/4 | 3/3명 (모두 참석 가능) |
| 3 | 11/2 | 2/3명 |
| 4 | 11/1 | 1/3명 |

결과 화면에서 기간을 「앞으로 2주」 등으로 바꾸면 그 기간으로 자른 뒤 다시 순위를 매긴다.

### ⑦ 약속

모임장 「가」가 약속 줄의 [+ 새 약속]으로 「송년회」(카테고리 술자리)를 만든다. 날짜는 아직 없다.

```
appointments.push({ id: 'Qw7…', roomId: 'aB3dEf', date: null, title: '송년회', category: 'drinks' })
```

결과 보기에서 11/3을 누르면 「이 날짜로 확정할 약속」에 송년회가 나온다. 고르고 [이 날짜로 확정]을 누른다.

```
appointments['Qw7…'].date = '2026-11-03'
```

약속 줄에 「11/3(화) 송년회 술자리」가 나오고, 약속을 누르면 「공지 복사」(`[동기 송년회] 송년회 · 11월 3일(화)에 만나요!` + 링크)와 초대장(술자리 테마로 바로 시작)을 쓸 수 있다. X는 그대로 남아서, 같은 모임에서 「신년회」 같은 다음 약속을 또 만들고 확정한다. 11/3이 지나면 송년회는 [지난 약속] 탭으로 간다.

## 데이터가 머무는 곳

| 데이터 | 지금 | 서버를 붙이면 |
|---|---|---|
| 계정·모임·참여·불가능한 날·메모·약속 | 이 브라우저의 localStorage (`eonje:db:v2`) | 서버 DB |
| 로그인 상태 | localStorage (`eonje:session:v1`) | 서버 세션 또는 토큰 |
| 화면 모드 | localStorage (`meetup.theme`) | 그대로 브라우저에 둔다 |
| 다른 탭으로 알림 | BroadcastChannel | 서버 실시간 구독 |

## 지금 상태 (2026-11-24)

- 서버 모드(Supabase)와 체험판 모두 쓸 수 있다. [README.md](../README.md)의 기능 표가 현재 범위다.
- `npm run check:tally` 통과, `npm run build` 성공.
- **이번에 바뀐 것**
  - 용어: 방 → 모임, 방장 → 모임장, 되는/안 되는 → 가능/불가능.
  - 처음 화면: [+ 모임 만들기]를 머리띠 오른쪽 끝으로, 최신순·가나다순 정렬, 성공 안내 문구 삭제, 빈 목록 안내 「아직 참여 중인 모임이 없어요✨」.
  - 모임 화면: 모임 이름 왼쪽 ✎ = 모임 설정(예전 「모임 메뉴」), 「○○님으로 참여 중 [이름 ✎]」 = 모임 안 이름, 모임원 패널은 입력한 사람만 ✓.
  - 약속: 「모임마다 확정 날짜 하나」를 「약속 여러 개」로 바꿨다(새 약속 → 날짜 골라 확정 → 지난 약속). 새 표 `appointments`, 새 함수 `rename_member`.
  - 디자인 두 번째 버전(스프링 벽걸이 달력, `look-mono.css`, `VITE_LOOK=mono`).
- **확인한 방법**: 이 서버에서는 브라우저를 띄울 수 없어(시스템 라이브러리 없음) 화면을 눈으로 보지 못했다. 대신 체험판 저장 로직을 Node에서 직접 돌려 확인했고(모임원은 약속을 못 만듦, 같은 날짜 중복 거부, 확정·취소·삭제 뒤에도 X·메모 유지, 예전 확정 날짜 옮기기, 이름 중복·길이 확인), 새 화면 조각은 서버 렌더링으로 그려 지는지만 봤다. 스프링 그림은 SVG를 PNG로 그려 확인했다.
- **Supabase에 아직 반영 안 됨**: 실제 Supabase 프로젝트에서 `schema.sql`을 다시 실행해야 약속과 모임 안 이름이 서버 모드에서 동작한다.

## 확인할 것

브라우저에서 확인하는 순서 (체험판이면 Supabase 없이도 된다: `.env.local` 없이 `npm run dev`)

1. 처음 화면: [+ 모임 만들기] 위치·크기, 모임 2개 이상일 때 정렬, 모임이 없을 때 안내 문구.
2. 모임 화면: ✎ → 모임 설정 창(모임장/모임원에 따라 다른 버튼), [이름 ✎]로 모임 안 이름 바꾸기(다른 사람 화면·메모 작성자에도 바뀌는지).
3. 약속: [+ 새 약속] → 결과에서 날짜 누르고 약속 골라 확정 → 약속 줄·달력 표시 → 약속 창(초대장, 공지, ✎, 날짜 확정 취소, 삭제) → 지난 약속 탭.
4. 모임원 계정으로 들어가 [+ 새 약속]·✎(약속)·「이 날짜로 확정할 약속」이 안 보이는지.
5. `VITE_LOOK=mono`로 띄워 스프링 위치·크기, 다크 모드에서 흰 스프링과 글자 대비.
6. 화면 모드(자동/라이트/다크)와 폭 390px에서 넘치는 곳이 없는지.

1. 위 「확인할 것」을 브라우저로 한 번 따라가기.
2. 디자인 고르기: 탁상 달력(기본)과 스프링 벽걸이 달력 중 하나로 정하면, 고른 쪽을 기본으로 두고 다른 쪽을 지운다.
3. SF겨울명조 파일 넣기(기본 디자인을 쓸 경우): 라이선스를 구매해 woff2 두 개를 `public/fonts/`에. 파일 이름은 [architecture.md](architecture.md)의 「글꼴과 글자 크기」.
4. 비밀번호 변경·회원 탈퇴 화면.
5. 정리할 것
   - `components/Sheet.jsx`의 `DayTile`은 어디서도 쓰지 않는다. 지우거나 쓰기로 정한다.
   - `RoomMenu.jsx`·`Room`·`RoomNew` 같은 코드 이름과 주소 `/r/:id`는 아직 「room」이다. 화면 문구만 「모임」으로 바꿨다.
   - 화면 모드 키 `meetup.theme`만 다른 키(`eonje:`)와 이름 규칙이 다르다. `eonje:`로 바꾸면 `useRoom`의 `storage` 리스너가 테마를 바꿀 때마다 모임을 다시 읽게 되므로 주의한다.
   - 다크 색이 `styles.css`·`look-mono.css` 안에 각각 두 곳씩 같은 값으로 있다. 하나를 고치면 짝도 고친다.
   - `meeting_app/README.md`가 언제볼래 설명을 담고 있다. `meeting_app/` 원래 설명으로 돌릴지 정한다.

## 남은 질문

| 질문 | 지금 가정 | 누가 답하나 | 영향 받는 곳 |
|---|---|---|---|
| 서버를 어디에 둘까? | Supabase | 팀 | `api/` 전체, 실시간 반영 |
| 계정이 꼭 필요한가, 모임마다 이름만 적게 할까? | 계정(이름 + 4글자 비밀번호) + 모임 안 이름 | 팀 (사용자 의견 확인) | 로그인, 내 모임 목록 |
| 한 모임 최대 8명이면 충분한가? | 8명 | 사용자 | `LIMITS.members` |
| 몇 달 앞까지 고를 수 있어야 하나? | 오늘부터 3개월 뒤 말일 | 사용자 | `WINDOW_MONTHS` |
| 확정 뒤 알림(카톡 공유 등)이 필요한가? | 공지 문구 복사·초대장 | 사용자 | 약속 창 |
| 약속은 모임장만 만들고 확정하나? | 모임장만 | 사용자 | `appointments` RLS, 약속 줄 |
| 같은 날짜에 약속 두 개가 필요한가? | 하나만 | 사용자 | `unique (room_id, date)` |
| 성공 기준(PRD Q6)을 어떤 모임으로 확인할까? | 미정 | 팀 | 서버 붙인 뒤 시험 운영 |
