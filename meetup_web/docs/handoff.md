# handoff.md — 언제볼래 인수인계

기준 문서: [PRD.md](PRD.md) v1.0 · 갱신일 2026-10-31
이 문서는 이어서 작업할 사람을 위한 것이다. 앞부분은 샘플 방 하나로 데이터가 어떻게 흐르는지 따라가고, 뒷부분은 지금 상태와 이어서 할 일, 남은 질문을 적는다.
구조와 데이터 모델은 [architecture.md](architecture.md)에 있다.

## 한눈에 보기

```
[로그인] 이름 + 4글자 비밀번호
    ▼
① 가입·로그인          users에 한 줄, 세션 시작
    ▼
② 방 만들기            rooms에 한 줄 + 방장 profiles 한 줄 → 링크·암호 복사
    ▼
③ 친구 참여            링크 열기 → (로그인) → 방 암호 → profiles 한 줄
    ▼
④ 안 되는 날 X         드래그 → 손 뗄 때 바뀐 날만 offDays에 반영 → 다른 탭에 알림
    ▼
⑤ 집계                 tally: 날짜마다 되는 사람 / 안 되는 사람          ← 규칙
    ▼
⑥ 순위                 ranking: 인원 많은 순, 같은 인원은 같은 순위       ← 규칙
    ▼
⑦ 확정                 방장이 날짜 하나 → rooms.confirmedDate → 공지 복사
```

AI는 어디에도 쓰지 않는다.

## 데모: 샘플 방 따라가기

`scripts/check-tally.mjs`와 같은 샘플을 쓴다. 세 사람 가·나·다, 기간은 11/1 ~ 11/4.

### ① 가입·로그인

「가」가 이름 `가`, 비밀번호 `1234`로 들어온다. 처음 보는 이름이라 가입할지 한 번 묻는다.

```
users['가'] = { name: '가', password: '1234', createdAt: '…' }
eonje:session:v1 = { name: '가', signedInAt: 1761…, lastSeen: 1761… }
```

### ② 방 만들기

「가」가 방 이름 `동기 송년회`, 암호 `2580`으로 방을 만든다. 만든 사람이 방장이고, 바로 참여한 상태가 된다.

```
rooms['aB3dEf'] = { id: 'aB3dEf', title: '동기 송년회', password: '2580', hostUser: '가', confirmedDate: null, … }
profiles += { id: 'a', roomId: 'aB3dEf', user: '가', name: '가', … }
```

복사되는 글: `[동기 송년회] 안 되는 날을 표시해 줘!\nhttp://…/r/aB3dEf\n암호: 2580`

### ③ 친구 참여

「나」·「다」가 링크를 연다. 로그인 전이면 주소를 기억해 두고 로그인 화면으로 갔다가, 로그인 후 방으로 돌아온다. 방 암호를 맞히면 profiles에 한 줄씩 생긴다. 8명이 차면 더 들어올 수 없다.

### ④ 안 되는 날 X

| 사람 | 안 되는 날 |
|---|---|
| 가 | 11/1 |
| 나 | 11/1 |
| 다 | 11/2 |

달력에서 첫 칸을 누를 때 그 칸이 비어 있으면 「표시」, 이미 X면 「지우기」로 정하고, 드래그하는 동안 같은 동작을 칠한다. 손을 떼면 실제로 바뀐 날만 `saveOffDays(roomId, [{ date, off }])`로 보낸다.

```
offDays = [
  { roomId: 'aB3dEf', profileId: 'a', date: '2026-11-01' },
  { roomId: 'aB3dEf', profileId: 'b', date: '2026-11-01' },
  { roomId: 'aB3dEf', profileId: 'c', date: '2026-11-02' },
]
```

저장 뒤 `offdays_changed`를 보내서, 같은 방을 연 다른 탭에 「방금 다님이 날짜를 바꿨어요」가 뜬다.

### ⑤ 집계 (`tally`)

| 날짜 | 되는 사람 | 안 되는 사람 |
|---|---|---|
| 11/1 | 다 | 가, 나 |
| 11/2 | 가, 나 | 다 |
| 11/3 | 가, 나, 다 | |
| 11/4 | 가, 나, 다 | |

### ⑥ 순위 (`ranking`)

| 순위 | 날짜 | 가능 |
|---|---|---|
| 1 | 11/3 | 3/3명 (모두 참석 가능) |
| 1 | 11/4 | 3/3명 (모두 참석 가능) |
| 3 | 11/2 | 2/3명 |
| 4 | 11/1 | 1/3명 |

결과 화면에서 기간을 「앞으로 2주」 등으로 바꾸면 그 기간으로 자른 뒤 다시 순위를 매긴다.

### ⑦ 확정

방장 「가」가 11/3을 누르고 [이 날로 확정]을 누른다.

```
rooms['aB3dEf'].confirmedDate = '2026-11-03'
```

방 맨 위에 확정 날짜가 나오고, 「공지 복사」로 `[동기 송년회] 11월 3일(화)에 만나요!` + 링크를 복사한다. 확정된 방은 안 되는 날을 바꿀 수 없다. 방장이 확정을 취소하면 다시 바꿀 수 있다.

## 데이터가 머무는 곳

| 데이터 | 지금 | 서버를 붙이면 |
|---|---|---|
| 계정·방·참여·안 되는 날·메모 | 이 브라우저의 localStorage (`eonje:db:v2`) | 서버 DB |
| 로그인 상태 | localStorage (`eonje:session:v1`) | 서버 세션 또는 토큰 |
| 화면 모드 | localStorage (`meetup.theme`) | 그대로 브라우저에 둔다 |
| 다른 탭으로 알림 | BroadcastChannel | 서버 실시간 구독 |

## 지금 상태 (2026-10-31)

- 체험판 기능은 모두 동작한다. [README.md](../README.md)의 기능 표가 현재 범위다.
- `npm run check:tally` 통과, `npm run build` 성공.
- 이전 작업에서 휴대폰 크기(390px) 브라우저로 처음부터 끝까지 확인했다(콘솔 오류 0건). 10분 로그인 유지도 확인했다(9분 뒤 유지, 11분 뒤 로그인 화면).
- **오늘 한 일**

  - 화면 모드 버튼을 추가했다: `components/ThemeToggle.jsx`, `App.jsx` 헤더, `styles.css`의 `[data-theme='dark']` 규칙과 버튼 스타일, `index.html`의 깜빡임 방지 스크립트. 폭 380px 이하에서는 아이콘만 보인다.
  - 빌드는 통과했지만 **화면 모드 전환은 브라우저에서 눈으로 확인하지 않았다.** 아래 「확인할 것」을 먼저 해 주세요.
  - 이 문서들(README, PRD, architecture, handoff)을 만들었다.
- **git**: `meetup_web/`과 `meeting_app/`은 아직 한 번도 커밋되지 않았다(untracked). 브랜치는 `feat/meeting-schedule`.

## 확인할 것

화면 모드를 브라우저에서 확인하는 순서

1. `npm run dev` 후 http://localhost:3058 을 연다.
2. 헤더 오른쪽 버튼이 「🖥️ 자동」인지 본다. 기기를 다크로 바꾸면 화면도 다크가 되는지 본다.
3. 버튼을 눌러 「☀️ 라이트」 → 기기가 다크여도 밝은 화면인지 본다.
4. 한 번 더 눌러 「🌙 다크」 → 기기가 라이트여도 어두운 화면인지 본다.
5. 다크 상태에서 새로고침 → 밝은 화면이 잠깐 비치지 않는지 본다.
6. 방 화면의 달력, 결과 순위, 날짜 상세 창, 알림이 두 모드에서 모두 읽히는지 본다.
7. 폭을 380px 이하로 줄이면 버튼에 아이콘만 남는지 본다.

## 이어서 할 일

우선순위 순서

1. **서버 저장 붙이기** (추천: Supabase). 이게 없으면 친구와 실제로 함께 쓸 수 없다. 방법은 [architecture.md](architecture.md)의 「서버로 옮기는 방법」.
2. 비밀번호와 방 암호를 해시로 저장하고, 확인을 서버에서 한다. 로그인 시도 횟수 제한을 둔다.
3. 비밀번호 변경·회원 탈퇴 화면.
4. 정리할 것
   - `components/Sheet.jsx`의 `DayTile`은 어디서도 쓰지 않고 스타일도 없다. 지우거나 쓰기로 정한다.
   - 화면 모드 키 `meetup.theme`만 다른 키(`eonje:`)와 이름 규칙이 다르다. 맞추려면 `index.html`과 `ThemeToggle.jsx`를 함께 고친다. `eonje:`로 바꾸면 `useRoom`의 `storage` 리스너가 테마를 바꿀 때마다 방을 다시 읽게 되므로 주의한다.
   - 화면 모드는 다른 탭에 바로 반영되지 않는다(새로고침하면 반영).
   - 다크 색이 `styles.css` 두 곳에 같은 값으로 있다. 하나를 고치면 다른 하나도 고친다.
   - `meeting_app/README.md`가 언제볼래(`meetup_web/`) 설명을 담고 있다. 이제 `meetup_web/README.md`가 있으니, `meeting_app/` 원래 설명으로 돌릴지 정한다.
