# PRD — 언제볼래

버전: v1.1 · 갱신일: 2026-11-24
이번에 바뀐 점: 「방장이 날짜 하나 확정」을 「모임은 계속 두고 약속을 쌓는 구조」로 바꿨다. 용어를 방→모임, 되는/안 되는→가능/불가능으로 통일했다. 서버 저장(Supabase)이 붙었다.

이 문서는 항상 현재 정답만 남긴다. 내용이 바뀌면 지우고 덮어쓴다.
사용자 인터뷰는 아직 하지 않았다. 아래 Q1·Q2·Q6은 만든 사람의 가정이고, 확인이 필요한 것은 「미확인」으로 표시했다.

## Q1. 누가 쓸까?

친구·동기 모임에서 약속 날짜를 잡는 일을 떠맡은 한 사람(총무 역할).
4~8명이 모이는 송년회나 정기 모임 날짜를 정하려고, 단톡방에 「언제 돼?」를 묻고 답을 모아 정리하는 사람이다.

(실제로 몇 명 규모의 모임이 가장 많은지, 몇 달 앞까지 잡는지는 미확인)

## Q2. 뭐가 답답한가?

1. 단톡방에 「되는 날 말해 줘」라고 올리면 답이 대화 사이에 흩어지고, 누가 답했는지 다시 확인해야 한다.
2. 「되는 날」을 다 적어 달라고 하면 적을 날이 많아 귀찮아서 답이 늦거나 오지 않는다. 사람들은 대개 「이날은 안 돼」가 더 빨리 떠오른다.
3. 모인 답을 손으로 세어 「모두 되는 날」을 찾다가, 누가 일정을 바꾸면 처음부터 다시 센다.

## Q3. 어떻게 풀까?

「모임 날짜를 잡는 총무를 위해, 친구들이 불가능한 날만 X 치면 모두 가능한 날을 순위로 바로 보여 주고, 같은 모임에서 다음 약속도 계속 잡게 해 주는 도구예요.」

## Q4. 기능 딱 3개

1. **불가능한 날 표시**: 달력에서 탭하거나 드래그해서 불가능한 날에 X를 친다. 손을 떼면 바로 저장된다. X는 약속과 상관없이 모임에 계속 남는다.
2. **가능한 날 집계와 순위**: 표시하지 않은 날은 가능한 날로 센다. 고른 기간 안에서 참석 가능한 인원이 많은 순으로 날짜 순위를 보여 주고, 날짜마다 불가능한 사람을 보여 준다. 집계는 규칙으로 처리하고 AI를 쓰지 않는다.
3. **약속 확정과 공유**: 모임장이 약속(이름·카테고리)을 만들어 두고, 날짜를 골라 그 약속으로 확정한다. 약속은 달력 위에 쌓이고(다가오는 약속 / 날짜 미정 / 지난 약속), 공지 문구 복사와 초대장 만들기를 할 수 있다.

이 셋을 받쳐 주는 것: 이름 + 4글자 비밀번호 로그인, 링크 + 숫자 암호로 모임 참여, 모임 안에서 쓰는 이름(닉네임), 날짜별 메모, 화면 모드(자동/라이트/다크).

안 할 것 (지금 범위 밖)
- 간편 로그인(Google·Apple), 즐겨찾기, 여러 모임에 내 날짜 한 번에 적용, 결제, 네이티브 앱
- 시간대(몇 시) 단위 일정 조율. 날짜 하루가 최소 단위다.

## Q5. 어떻게 생겼나?

- **로그인**: 이름과 4글자 비밀번호. 처음 보는 이름이면 가입할지 한 번 묻는다.
- **처음 화면**: 머리띠 「○○님의 모임」 오른쪽 끝에 [+ 모임 만들기]. 내가 속한 모임 목록(모임장 표시, 인원 수, 최신순·가나다순, 모임장은 삭제·모임원은 나가기), 받은 링크 붙여넣기 칸.
- **모임 화면**
  - 머리띠: 모임 이름 왼쪽 ✎ → 모임 설정(링크 복사, 이름·암호 변경, 삭제/나가기).
  - 「○○님으로 참여 중 [이름 ✎]」: 이 모임에서 쓸 이름.
  - 약속 줄: [+ 새 약속] · 다가오는 약속 · 날짜 미정 약속 · 오른쪽 끝 [지난 약속].
  - 탭 [불가능한 날]: 한 달씩 넘기는 달력에 X. 「저장됨 ✓ 시각」이 보인다.
  - 탭 [결과 보기]: 기간 칩과 날짜 직접 입력 → 달력(모두 가능한 날은 꽉 채우고, 적을수록 흐리게) → 날짜 순위 카드.
  - 날짜를 누르면 가능한/불가능한 사람, 메모, (모임장) 이 날짜로 확정할 약속 고르기.
  - 오른쪽 모임원 패널: 날짜를 입력한 사람 옆에 ✓.
- 모든 화면 위쪽 헤더 오른쪽에 화면 모드 버튼이 있다. 디자인은 탁상 달력(기본)과 스프링 벽걸이 달력 두 가지.

## Q6. 성공의 모습

(제안, 미확인) 4명 이상이 모인 실제 모임 하나에서, 총무가 링크를 보낸 뒤 모든 사람이 각자 X 표시를 마치고, 총무가 단톡방에서 따로 다시 묻지 않고 결과 순위만 보고 날짜를 확정하면 성공.

지금은 체험판이라 이 기준을 확인할 수 없다. 서버 저장을 붙인 뒤 측정한다.

## 데이터·제약

- 쓸 수 있는 자료: 없음. 사용자가 직접 입력하는 이름·날짜·메모만 다룬다.
- 저장: 서버 모드는 Supabase, 설정이 없으면 이 브라우저의 localStorage(체험판).
- 보안: 서버 모드에서 계정 비밀번호와 모임 암호는 bcrypt로 저장하고, 5번 틀리면 5분 잠근다. 모임 데이터는 그 모임 멤버만 읽고, 약속은 모임장만 만들고 고친다(DB의 RLS). 체험판은 브라우저에 그대로 저장한다.
- 비용: Supabase·Vercel 무료 요금제 안에서.

## 한 단락 PRD

친구·동기 모임에서 날짜를 잡는 총무는 단톡방에서 가능한 날을 묻고 흩어진 답을 손으로 세는데, 가능한 날을 다 적어 달라고 하면 답이 늦고 누가 일정을 바꾸면 처음부터 다시 센다. 같은 친구들과 약속을 계속 잡는데도 매번 처음부터 다시 묻는다. 이 총무를 위해, 친구들이 불가능한 날만 X 치면 모두 가능한 날을 순위로 바로 보여 주고, 한 모임 안에서 다음 약속도 계속 잡게 하는 웹앱을 만든다. 반드시 만들 기능은 세 가지다. (1) 달력에서 탭하거나 드래그해서 불가능한 날을 표시하고 손을 떼면 바로 저장한다. (2) 표시하지 않은 날은 가능한 날로 세어, 고른 기간 안에서 참석 가능한 인원이 많은 순으로 날짜 순위를 보여 준다. 집계는 AI가 아닌 규칙으로 처리한다. (3) 모임장이 약속을 만들어 두고 날짜를 골라 확정하며, 약속은 다가오는 약속·날짜 미정·지난 약속으로 쌓이고 공지 문구와 초대장으로 공유한다. 사용자는 이름과 4글자 비밀번호로 로그인하고, 링크와 숫자 암호로 최대 8명이 한 모임에 참여하며, 모임 안에서 쓸 이름을 따로 정할 수 있다. 간편 로그인·결제·네이티브 앱·시간 단위 조율은 하지 않는다. 실제 모임 하나에서 모두가 표시를 마치고 총무가 따로 묻지 않고 결과만 보고 약속을 확정하면 성공이다.
